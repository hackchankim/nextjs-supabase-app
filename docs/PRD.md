# 교회 마피아 게임 프로젝트 PRD

> 이 문서는 두 파트로 구성된다. **Part 0(자율 개발 에이전트 팀)** 을 **먼저** 구축하고, 그 팀이 **Part 1(교회 마피아 게임)** 을 (반)자율로 개발한다. Part 0 = 개발 시스템 부트스트랩, Part 1 = 그 시스템으로 만드는 제품.

## 📌 개발 순서 (선행 → 본 개발)

1. **Part 0 — 자율 개발 에이전트 팀 인프라 (선행 · 최우선)**: 스스로 개발하고, 산출물을 코드리뷰·QA하며, 중요 의사결정 시 카카오톡으로 알리는 개발 시스템을 먼저 구축한다.
2. **Part 1 — 교회 마피아 게임 MVP (본 개발)**: Part 0의 에이전트 팀이 **Shrimp Task Manager + `docs/ROADMAP.md`** 흐름(`plan_task → list_tasks → execute_task → verify_task`)으로 구현한다.

# 🤖 Part 0. 자율 개발 에이전트 팀 인프라 (선행 개발)

## 🎯 핵심 정보

**목적**: 개발자가 자리를 비워도 스스로 개발을 진행하고, 산출물을 자동으로 코드리뷰·QA한 뒤, 중요 의사결정이 필요할 때 카카오톡으로 알림을 보내는 (반)자율 개발 에이전트 팀을 구축한다
**사용자**: 이 저장소에서 마피아 게임을 개발하는 1인 개발자(운영자), 그리고 저장소를 pull 받아 동일 환경을 세팅하는 협업자

## 🔒 안전 원칙

- 에이전트는 **새 브랜치에만 커밋하고 PR을 생성**한다. `main` 병합·배포는 **사람이 승인**한다 (human-in-the-loop).
- 되돌리기 어려운 결정(DB 스키마 변경·외부 서비스 연동·비가역 작업)은 자동화하지 않고 **카카오 알림으로 사람에게 넘긴다**.
- 시크릿(카카오·GitHub·Supabase 키)은 **절대 커밋하지 않는다** (다층 방어 · D008).

## 🔁 개발 파이프라인

```
트리거(로컬 /loop·cron  또는  GitHub 이슈/PR @claude)
      ↓
오케스트레이터(/dev:auto-dev)
  1) docs/ROADMAP.md 확인 → 현재 Phase 식별 (예: "Phase 1: 애플리케이션 골격 구축")
  2) shrimp plan_task("Phase N: <제목>", @docs/ROADMAP.md)  → 태스크 분해·생성
  3) shrimp list_tasks                                       → 다음 pending 태스크 1건 선택
  4) shrimp execute_task(<id>)  →  적합한 서브에이전트에 위임
      ↓
게이트: npm run lint + npm run typecheck (+ Playwright 스모크)
      ↓
code-reviewer(정적 리뷰) → 반영
      ↓
qa-tester(앱 실제 실행 + Playwright MCP 동작 테스트) → 결함 시 개발 단계로 반려(최대 N회)
      ↓
shrimp verify_task(<id>) → 새 브랜치 커밋 → PR 생성 (main 직접 커밋 금지)
      ↓
docs:update-roadmap (shrimp 상태 ↔ ROADMAP 체크마크 동기화)
      ↓
[의사결정 필요/막힘] → 카카오 알림 + docs/decisions/ 로그 후 정지
[작업 완료]         → 카카오 알림("PR #N 준비됨") → 다음 pending 태스크
```

# 🎮 Part 1. 교회 테마 마피아 게임 MVP

> 아래 제품 스펙은 **Part 0의 자율 개발 에이전트 팀이 개발**한다.

## 🎯 핵심 정보

**목적**: 교회 레크리에이션 행사에서 10-20명이 각자 모바일 브라우저로 접속해 앱 설치 없이 즉시 즐기는 실시간 마피아 게임을 제공한다
**사용자**: URL 하나로 바로 참여하려는 교회 성도 10-20명과, 게임 전체를 운영하는 진행자 1명

---

## 🚶 사용자 여정

```
[참가자]
1. 입장 허브 페이지
   ↓ 닉네임 입력 → 입장 버튼
2. 대기실 페이지 (다른 성도 모집 대기 · 원하면 [나가기]로 퇴장 가능)
   ↓ 진행자가 게임 시작 → 자동 이동
3. 게임 플레이 페이지
   ↓ 역할 카드 확인 (1회 애니메이션)

4. [낮 페이즈] 전체 채팅 토론 (+ 1:1 비밀 채팅) → 투표
   ↓ 진행자 투표 마감(또는 전원 투표 시 조기 종료) → 최다 득표자 탈락

5. [밤 페이즈]
   이단 대장 → 이단 비밀 채팅 + 제거 대상 선택 (제거 선택은 대장만)
   이단 → 이단 비밀 채팅으로 작전만 공유
   목사님 → 조사 대상 선택 (이단 여부를 본인에게만 알림, 이단 대장도 이단으로 식별)
   장로님 → 당회 비밀 채팅으로 목사님과 정보 공유 (밤 행동 없음)
   권사님 → 보호 대상 선택
   성도 → 기도 대기 화면
   ↓ 결과 처리 후 낮으로 반복

6. 승리 조건 달성 → 게임 종료 화면 (승리 팀 발표)

[진행자]
1. 입장 허브 페이지
   ↓ 진행자 PIN 입력
2. 진행자 대시보드 페이지
   스크린에는 [스크린 탭] 띄우고 / 개인 폰에서 [제어 탭] 조작
   ↓ 참가자 확인 → 게임 시작 → 페이즈 전환(10초 카운트다운·취소 가능) 반복 → 게임 종료
```

## ⚡ 기능 명세

### 1. MVP 핵심 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F001** | 닉네임 입장 | 닉네임 입력 후 세션 토큰 발급, 로그인 없이 즉시 참가 | 회원가입 없는 즉시 참가가 일회성 행사의 핵심 | 입장 허브 페이지 |
| **F002** | 진행자 PIN 입장 | 4자리 PIN으로 진행자 권한 획득 | 게임 제어 권한 구분을 위한 최소 수단 | 입장 허브 페이지 |
| **F003** | 대기실 실시간 목록 | 접속 참가자 닉네임 목록 실시간 표시 | 참가자가 제대로 입장했는지 확인하는 핵심 화면 | 대기실 페이지 |
| **F004** | 역할 자동 배분 | 인원수 기반 선/악 역할 무작위 배분 후 게임 시작 | 공정한 역할 분배가 게임의 시작점 | 대기실 페이지, 진행자 대시보드 페이지 |
| **F005** | 역할 카드 공개 | 게임 시작 시 개인 폰에 자신의 역할 1회 표시 | 비밀 역할 확인이 마피아 게임의 핵심 경험 | 게임 플레이 페이지 |
| **F006** | 낮/밤 페이즈 전환 | 진행자 제어로 페이즈 전환, 전원 화면에 실시간 반영 | 게임 진행의 근간이 되는 상태 관리 | 게임 플레이 페이지, 진행자 대시보드 페이지 |
| **F007** | 전체 채팅 | 낮 페이즈에 전원이 참여하는 실시간 채팅 | 토론으로 이단을 색출하는 게임의 핵심 메카닉 | 게임 플레이 페이지 |
| **F008** | 이단 비밀 채팅 | 이단·이단 대장 역할끼리만 보이는 비밀 채팅방 | 이단 팀의 작전 채널, 게임 긴장감의 원천 | 게임 플레이 페이지 |
| **F009** | 낮 투표 시스템 | 퇴장 대상 선택 + 집계, 진행자 마감 후 최다 득표자 탈락 | 선 팀의 핵심 공격 수단 | 게임 플레이 페이지, 진행자 대시보드 페이지 |
| **F010** | 밤 행동 | 역할별 특수 행동 (이단 대장: 제거 / 목사님: 조사 / 권사님: 보호). 대상은 클릭 즉시 실행되지 않고 먼저 하이라이트로 "선택"한 뒤 별도의 확정 버튼을 눌러야 실행되는 2단계 흐름이며, 확정 후에는 해당 밤 페이즈 동안 대상을 바꿀 수 없다(페이즈당 1회 확정, 다음 밤까지 잠금). 이 선택→확정·페이즈당 1회 잠금 규칙은 이단 대장·목사님·권사님 3개 역할 모두에 동일하게 적용된다. 확정 후에는 패널에 확정된 대상이 계속 표시되며, 목사님의 조사 결과는 그 밤이 끝날 때까지 패널에 지속 표시된다(본인에게만 보이며 DB·다른 참가자에게는 노출되지 않음). 제거 대상 선택은 이단 대장만 가능, 일반 이단은 채팅으로 작전만 참여. 목사님 조사는 이단·이단 대장을 모두 "이단"으로 정확히 식별(위장 없음) | 밤마다 발생하는 핵심 게임 메카닉 | 게임 플레이 페이지 |
| **F011** | 생존 현황 | 생존/탈락 플레이어 목록 실시간 표시 | 게임 진행 상황 파악의 기본 정보 | 게임 플레이 페이지, 진행자 대시보드 페이지 |
| **F012** | 스크린용 현황판 | 역할 비공개 상태로 닉네임·생존 현황만 표시 (빔프로젝터용) | 스크린에 역할이 노출되면 게임이 망가지므로 분리 필수 | 진행자 대시보드 페이지 |
| **F013** | 진행자 전용 제어판 | 역할 포함 전체 현황 + 게임 컨트롤 (진행자 개인 폰에서만 조작) | 진행자만 볼 수 있는 비밀 정보로 공정한 게임 운영 | 진행자 대시보드 페이지 |
| **F014** | 승리 조건 판정 | 선/악 승리 조건 자동 체크 후 게임 종료 및 결과 표시 | 게임의 명확한 결말 제공 | 게임 플레이 페이지, 진행자 대시보드 페이지 |
| **F015** | 당회 비밀 채팅 | 목사님·장로님(당회)끼리만 보이는 비밀 채팅방 | 선 팀 리더십이 조사 정보를 공유하는 핵심 협력 채널 | 게임 플레이 페이지 |
| **F016** | 1:1 비밀 채팅 | 상대를 지정해 둘만 보는 귓속말, 낮 페이즈·생존자만 가능 | 은밀한 설득·연합 형성으로 토론에 깊이 부여 | 게임 플레이 페이지 |
| **F017** | 페이즈 전환 카운트다운 | 낮/밤 전환 시 전원 화면에 10초 카운트다운 표시, 진행자가 도중 취소 가능 | 갑작스러운 전환 방지 및 진행자의 운영 여유 확보 | 게임 플레이 페이지, 진행자 대시보드 페이지 |
| **F018** | 투표 조기 종료 | 생존자 전원 투표 완료 시 진행자가 투표를 즉시 마감 | 불필요한 대기 없이 게임 템포 유지 | 진행자 대시보드 페이지 |
| **F019** | 참가자 강퇴/관리 | 진행자가 참가자를 강퇴 (대기실=목록에서 제거, 게임 중=탈락 처리 후 승리 조건 재검사) | 로그인/통신 오류로 잘못 들어온 인원·유령·중복 참가자 정리로 정상 진행 보장 | 대기실 페이지, 진행자 대시보드 페이지 |
| **F020** | 접속 상태 표시 | Realtime Presence 기반으로 각 참가자의 온라인/오프라인 상태를 진행자 화면에 배지로 표시 | 통신 장애 참가자를 식별해 강퇴 판단의 근거 제공 | 대기실 페이지, 진행자 대시보드 페이지 |
| **F021** | 참가자 자발적 퇴장 | 대기 중 참가자가 본인 세션(session_token)으로 스스로 퇴장 — 레코드 삭제 후 전원 목록에서 실시간 제거. 게임 시작(day/night) 후에는 불가 | 잘못 입장·변심한 참가자가 진행자를 기다리지 않고 스스로 정리해 대기실을 깔끔히 유지 | 대기실 페이지 |

### 2. 설계 원칙: 역할 무차별 UI

옆 사람이 화면을 슬쩍 봐도 역할이 드러나지 않도록, **모든 참가자의 게임 플레이 화면은 레이아웃·탭 구성·색상 테마가 동일**해야 한다.

- **중립 테마**: 역할별 색상/배지/아이콘을 메인 화면에 노출하지 않는다 (이단 전용 색상 테마 금지).
- **비밀 채널 탭 통일**: 전원에게 "비밀 채널" 탭이 동일하게 1개 존재한다. 멤버십에 따라 내용만 분기 — 이단 팀은 이단 채팅, 당회(목사님·장로님)는 당회 채팅, 그 외(성도·권사님)는 구조가 동일해 보이는 개인 플레이스홀더(예: 개인 기도 메모)를 본다. 탭의 유무·라벨로 역할이 드러나지 않는다.
- **밤 행동 패널 통일**: 전원이 동일한 형태의 "대상 선택" 패널을 본다. 능력이 없거나 권한이 없는 역할(성도, 일반 이단 등)에게도 동일한 UI를 보여주되 실제 동작은 no-op 처리한다. 대상 선택 후 별도 확정 버튼으로 실행하는 2단계 흐름과, 확정 후 해당 밤 페이즈 동안 잠기는 규칙(페이즈당 1회 확정)도 역할 구분 없이 모든 역할에 동일하게 적용된다.
- **역할 정보는 1회 모달로만**: 자신의 역할은 시작 시 역할 카드 모달에서만 확인하며, 모달 구조는 모든 역할이 동일하다.

- **Supabase Realtime** - 채팅·플레이어 목록·게임 상태 실시간 동기화
- **Supabase Realtime Presence** - 참가자 온라인/오프라인 접속 상태 추적 (강퇴 판단 근거)
- **Supabase RLS** - 비밀 채널 접근 제어 (이단 채널: 이단 팀만 / 당회 채널: 목사님·장로님만 / 1:1 채널: 발신자·수신자만 열람 가능)

### 배포
